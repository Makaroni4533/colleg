# NetLab · Сетевое программирование

Практические работы №5–8 на Node.js 22+ без npm-зависимостей. Все команды ниже выполняются из корня репозитория.

| Работа | Каталог | Транспорт |
| --- | --- | --- |
| №5. Многоклиентский сервер | `netlab-05` | TCP 3020 |
| №6. Оповещения | `netlab-06` | UDP 3030 |
| №7. Сервер и REST API | `netlab-http` | HTTP 3041 |
| №8. Клиент с fetch | `netlab-http-client` | HTTP 3041 |

## №5. TCP

Запустите `node netlab-05/server.mjs`. В отдельных терминалах откройте несколько экземпляров `node netlab-05/client.mjs`.

| Команда | Ответ или действие |
| --- | --- |
| PING | PONG |
| SAY Привет | Рассылка остальным клиентам и SENT отправителю |
| STATS | Число клиентов и команд текущего пользователя, включая STATS |
| WHO | Имена и клиентские порты |
| HELP | Список команд |
| IDLE | Тайм-аут в секундах |
| QUIT | BYE и закрытие соединения |
| HELLO | ERROR UNKNOWN_COMMAND, можно затем выполнить PING |

После QUIT проверьте PING на втором клиенте. Шестое одновременное подключение получает ERROR SERVER_FULL. Для сравнения с исходным лимитом из методички запустите сервер после `$env:NETLAB_MAX_CLIENTS = '3'`. Затем удалите переменную через `Remove-Item Env:NETLAB_MAX_CLIENTS`.

После 15 секунд без входящих данных приходит WARNING IDLE, после 20 секунд — ERROR IDLE_TIMEOUT. Строка длиннее 1024 байт вызывает ERROR LINE_TOO_LONG. При занятом порте второй сервер сообщает EADDRINUSE. После остановки сервера клиент сообщает ECONNREFUSED.

TCP передаёт поток байтов. Сервер собирает строки отдельно для каждого сокета и выделяет команды по переводу строки. Событие close удаляет запись из Map и останавливает таймеры, освобождая место для нового клиента.

## №6. UDP

Первый терминал: `node netlab-06/receiver.mjs`. Второй: `node netlab-06/sender.mjs unicast 127.0.0.1 "Проверка связи"`. Введите STOP в терминале приёмника для завершения.

| Режим | Назначение | Подписка |
| --- | --- | --- |
| Unicast | IP одного компьютера | Нет |
| Broadcast | Broadcast-адрес IPv4-подсети | Нет |
| Multicast | 239.255.10.10 или 239.255.10.11 | Да |

- Для broadcast определите адрес учебной подсети по IP и маске. Для сети 192.168.1.0/24 пример команды: `node netlab-06/sender.mjs broadcast 192.168.1.255 "Начинаем занятие"`.
- Для multicast запустите приёмник с аргументом `1`, `2`, `both` или `none`. Аргумент по умолчанию — `1`. По очереди отправьте `node netlab-06/sender.mjs multicast 239.255.10.10 "Группа 1"` и аналогичную команду на `239.255.10.11`. Для явного выбора интерфейса установите `MULTICAST_IFACE` в локальный IPv4-адрес каждого компьютера.
- Схема групповой передачи: отправитель → локальный интерфейс → IPv4-группа → подписанные приёмники. Отправителю достаточно одного вызова send, а подтверждение доставки UDP отсутствует.
- Для оповещений всему классу подходит multicast, когда все учебные ПК подписаны на группу и сеть поддерживает групповую передачу. Broadcast охватывает весь IPv4-сегмент.
- В журнале опыта для каждого режима укажите адрес назначения, компьютеры, получившие сообщение, и наблюдаемый результат. Проверка между двумя ПК требует доступа к учебной сети.

## №7. HTTP API

Запустите `node netlab-http/server.mjs` и откройте [страницу NetLab](http://127.0.0.1:3041/).

| Метод и путь | Результат |
| --- | --- |
| GET /api/status | Статус, счётчик событий и запросов |
| GET /api/about | Название и версия |
| GET /api/stations | Три учебные станции |
| GET /api/events | Список событий |
| POST /api/events | Создание события, 201 и Location |
| GET /api/events/1 | Событие или 404 |
| DELETE /api/events/1 | 204 или 404 |
| GET /api/slow?ms=3000 | Ответ после задержки |
| GET /api/error | 503 |

POST принимает JSON с полями station и message. Повреждённый JSON и пустые поля дают 400, неподдерживаемый тип тела — 415, тело больше 4096 байт — 413. Неподдерживаемый метод на существующем маршруте даёт 405 с Allow. События хранятся в памяти процесса. Запустите медленный запрос и сразу откройте /api/status во второй вкладке: таймер позволяет обработать второй запрос, пока первый ждёт.

## №8. HTTP-клиент

С запущенным HTTP-сервером выполните:

```powershell
node netlab-http-client/client.mjs demo
node netlab-http-client/client.mjs status
node netlab-http-client/client.mjs events
node netlab-http-client/client.mjs send PC-07 "Нужна помощь"
```

Демонстрация показывает HTTP-статусы, response.ok, заголовки, тело и длительность запросов. Маршрут с задержкой 3000 мс прерывается при бюджете 1000 мс и успевает ответить при 4000 мс. HTTP 404 и 503 приходят как Response с ok: false. При остановленном сервере команда status показывает ECONNREFUSED и повторяет GET один раз. POST выполняется один раз, чтобы повтор не создавал дубликаты. Content-Type описывает формат тела, а Cache-Control: no-store запрещает сохранять ответ в кэше.
